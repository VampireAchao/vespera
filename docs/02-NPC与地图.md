# 02 · NPC 与地图

这篇回答两个问题：**人怎么站在世界里**，以及**世界怎么被造出来并纳入版本管理**。

---

## 一、NPC 的四种做法

| 做法 | 客户端要求 | 能做 | 不能做 | 维护成本 | 结论 |
|---|---|---|---|---|---|
| **原版实体 + 持久化身份**（本仓库已实现） | 无 | 站桩、名字、右键说话、被推动关闭、无 AI | 皮肤、走动、看向、血条 | 极低 | ✅ P0 基线 |
| **Citizens** | 无 | 皮肤、走动、巡逻、看向、装备、NPC 商店、API 完整 | 需要额外 jar；OSL-3.0；随 Paper 版本升级 | 中 | ✅ P2 升级 |
| **数据包 `summon` + 命令方块** | 无 | 任何原版实体，含自定义 NBT | 逻辑要写在函数里，条件一复杂就不可读 | 高（且难 review） | ❌ |
| **自研 packet NPC**（PacketEvents / 假玩家） | 无 | 完全可控，能做到"玩家皮肤 + 无实体碰撞" | 协议随版本变；自己实现寻路/皮肤/动画 | 很高 | ❌ 除非要做上百个 |

### 关键设计：身份与渲染分离

```
   npcId = "bell-monk"          ← 身份。写在实体的 PDC 里，重启、换区块、被 /kill 都认得回来
        │
        ├── 渲染 A：原版村民（零依赖，setAware(false)）
        └── 渲染 B：Citizens NPC（P2 接入，同一坐标，同一个 npcId）
```

所有剧情、对话、旗标只认 `npcId`，不认实体类型、不认 UUID、不认坐标。这样：

- 换成 Citizens 时，剧本一行都不用改；
- 锚点被误删，`/vespera npc` 重建即可，玩家的好感与旗标不受影响；
- 同一个角色可以在两个地方出现（本人 + 回忆里的幻影），只要换 id。

### 24 位有名 NPC 的能力需求

设计书要求 24 位有名 NPC + 60 位无名 NPC。按"必须有什么"分层，可以省下大量工作：

| 层级 | 数量 | 需要什么 | 实现 |
|---|---|---|---|
| 核心角色（贝尔纳、薇拉、塞拉菲娜、卡西安……） | 8 | 皮肤、专属对话、专属羁绊事件、可能走动 | Citizens + 对话图 + 条件 |
| 教职员（格蕾丝、阿德莱德、戈登……） | 8 | 站桩、大量对话、考试判定 | 锚点 + 对话图 + 小游戏 |
| 同学与室友（卢卡、塞西尔、诺亚……） | 8 | 站桩、好感、四层筛选台词 | 锚点 + 好感计数 |
| 无名（门房、摊主、路人） | 60 | 一两句话，或只有名字 | 锚点（低成本）+ 单节点对话 |

**结论：只有 8 个 NPC 真的需要 Citizens。** 其余 16 + 60 个用锚点就够，且锚点不占算力。

### 实现要点（已经写在代码里，这里说为什么）

| 要点 | 原因 |
|---|---|
| 身份存在 `PDC` 而不是坐标表 | 坐标会变（换地图、改布局），PDC 跟着实体走 |
| `setAware(false)` + `setSilent(true)` + `setInvulnerable(true)` | 站桩的人不该 tick AI、不该叫、不该被僵尸打死 |
| 右键事件 `setCancelled(true)` | 不拦的话原版村民会弹出交易界面，压在我们的对话上面 |
| 潜行右键不触发 | 给"想看看这个人叫什么"留一个不打断的操作 |
| 下线即撤（`onDisable` 清空） | 世界文件里不留一堆实体；重开按配置重建，配置才是真相 |

### 对话的五个入口

NPC 只是入口之一。同一个对话图可以从五个地方打开，这让"触发方式"变成配置而不是代码：

| 入口 | 场景 | 实现 |
|---|---|---|
| 右键 NPC | 常规对话 | `PlayerInteractEntityEvent` + PDC 身份 |
| 右键物品 | 一封信、一颗珍珠、一张学生证 | `PlayerInteractEvent` + 物品 PDC |
| 进入区域 | 走进档案室就听见有人说话 | `PlayerMoveEvent` + 区域判定（或用 WorldGuard 区域事件） |
| 定时/条件 | 晚钟后回宿舍，室友在等你 | 时钟段切换 + 条件判定 |
| 命令 | 剧情强制推进、测试 | `/vespera talk <id>` |

## 二、地图：三层资源，各管各的

把"地图"这个词拆开，是这件事能管起来的前提：

| 层 | 是什么 | 载体 | 谁改 | 进 git 吗 |
|---|---|---|---|---|
| **地形** | 山川、河流、生物群系 | 世界种子 + WorldPainter 工程（`.world`） | 关卡 | 工程进，`region/` 不进 |
| **建筑** | 一栋楼、一座桥、一个祭坛 | `.schem` + `layouts/*.yml` | 建筑 | 进（LFS） |
| **装饰** | 箱子里的书、告示牌、刷怪点、NPC 站位 | 数据包 + 插件配置 | 策划 | 进 |

### 已建成：流明陨城

主城不再是"灰盒"，而是一座 600×600 的城市：四门十二塔的城墙、十字大街、中央市集、
哥特大教堂（双塔 110 格）、城堡（台地 + 幕墙 + 主楼）、市政厅、行会厅、工匠街、
200 余栋半木民居、南港、竞技场、西田与北村。约 150 万方块。

- 城区与墙外的布局、分区表、建筑语汇见 **[08-主城设计](08-主城设计.md)**。
- 验收图与规划图在 `docs/设计图/`。
- 世界是**正常地形**：城是整平出来的台地，墙外仍是原版地貌；水面区域由落地器先挖后灌，
  不会出现"水埋在地里"。

### 已定的形态：混合

四个维度，全是原版维度。玩家用原版手段就能走完——**没有一处需要命令传送**。

| 维度 | 放什么 | 怎么到 | 为什么这样放 |
|---|---|---|---|
| `world` | 六区连成一块大陆 | 从出生点**走过去** | 走过一次的路会变成记忆；传送一次的路只是一个按钮 |
| `world_nether` | 熔炉之喉 | ① 主城的门（被定向）② 荒野搭门自己走过来 | 下界本来就该用门；定向只是让"主城那几扇门"有共同的目的地 |
| `world_the_end` | 珍珠荒原（外岛西北象限） | 折跃门，或一颗末影珍珠硬闯 | 外岛是末地自己的地理，不需要额外解释 |
| `world_sunwheel` | 日轮庭院（轮心） | 终局入口 | 这一步是"进去"，不是"走到" |

**坐标只有一处真相：`regions/regions.yml`。** 地图组按它建造，插件按它判定，
`docs` 按它画图。`layouts/world.yml` 只讲关系与手法，不重复坐标——重复的坐标迟早会漂。

### 现在能进去看的：两片灰盒

规划之外，先盖了两版**能走进去的灰盒**（greybox）。这不是终稿，是"空间对不对"的答案。

| | 流明陨城（主城） | 钟塔学院 |
|---|---|---|
| 位置 | 世界出生点 (0,0) | 城东约 370 格，隔一条河 |
| 体量 | 300×300 城墙 + 28 处地物 + 15 栋民居 | 11 栋楼 + 7 段回廊 + 腰高围墙 |
| 方块数 | 约 8.1 万，约 1 秒 | 约 4.7 万，约 0.5 秒 |
| 默认 | 自动建造 | 默认关闭（`/vespera build campus` 手动开） |
| 图纸 | `docs/设计图/流明陨城平面图.html` | `docs/设计图/学院平面图.html` |
| 怎么改 | 改 `CityPlan` / `CampusPlan` → 版本号加一 → 重开；或 `vesper build` | 同左 |

**为什么先建主城，而不是学院。**

第一版先做了学院，理由是设计书里只有学院篇给了"十一栋楼 + 每栋为什么在那儿"的逐条表，
主城只有一句"300×300、出生点、市集、钟楼"。这是把"资料最全的地方"当成了"最该先做的地方"。

真正的判据不是资料多少，而是**玩家第一眼看到什么**：

- 出生点在主城。进服站在学院门口，等于把"家"和"学校"的位置搞反了。
- 四十二条主线从主城出发。主城是"你回来了"的地方，学院是"你去过一段日子"的地方——
  先有回来的地方，日子才有落点。
- 钟楼定天际线。主城的钟楼 54 格，学院最高的只有 46 格；这两条线谁高，决定了玩家
  第一次抬头时世界的重心在哪。

所以现在的顺序是：**城 → 校**。`city.auto` 默认 true，`campus.auto` 默认 false。

灰盒里真实成立的东西（这些比材质重要）：

- **十字主街**从四个门通向广场，走进去不需要看地图。
- **钟楼压在一排屋顶上**——54 格对 11 格，天际线是设计过的，不是等高的方块堆。
- **城墙 8 格带雉堞**：翻不过去，但看得见里面。
- **回廊全都有顶**（学院），从宿舍到教学楼不露天——吸血鬼那条机制才有地方站。
- **体育馆没有天窗**、**锅炉房真在地下**、**围墙只到腰高**。

还没做的：室内家具、教室分隔、楼梯转接（现在是直梯井）、地形融合。这些属于 P1 的美术与
关卡工作，不影响"走过去看一眼"。

### 下界门怎么"定向"

原版下界门只按 **1:8** 换算坐标，不认"这是哪一扇门"。所以要同时满足
"走特定传送门能到熔炉之喉"和"自己搭门也能在荒野探索"，只有一个办法：
**在传送发生的那一刻改写落点。**

```
玩家走进一扇下界门
      ↓
PlayerPortalEvent（cause = NETHER_PORTAL）
      ↓
他在哪个区域？（RegionBook.at）
      ↓
lumenfall → 落点改写为 熔炉之喉入口平台，且不生成新门
其余任何地方 → 原版行为，照常 1:8 换算
```

三条实现细节，都是踩过才知道的：

| 细节 | 为什么 |
|---|---|
| 按**区域**匹配，不按方块坐标 | 玩家会在自家地下室搭门，位置不可预测；按区域才能覆盖"城里所有的门" |
| `setCanCreatePortal(false)` | 不关的话，入口平台会自己长出一圈门，越跑越乱 |
| 只处理 `NETHER_PORTAL` | 末地折跃门是原版机制，插手反而会破坏"外岛靠自己走过去"的设计 |

**一条容易被忽略的硬约束：** 恶魔"洗火"（还人）要求玩家在寒带生物群系溺水。所以
寒带水域必须真实存在，且离熔炉之喉足够远——这段路本身就是支线 S-07「三十个冬天」。
地图不是背景，地图是规则的一部分。

### 世界边界：不设 `worldborder`

混合形态的第一条美术禁令：**不许出现直线边界。**

需要"尽头"的地方，用海、崖、虚空，以及"被擦掉"的地形（半截建筑、断树）。
`worldborder` 是一道看不见的墙，它会把"世界正在被擦掉"变成"服务器限制了活动范围"——
前者是设定，后者是抱怨。

### 工作流

```
WorldPainter（地形）
      ↓  导出世界
WorldEdit（在服务器里精修、试走、量尺寸）
      ↓  //copy → //schem save college/gate-v1
.schem（一栋楼一个文件）  →  git LFS
      ↓  写进 layouts/college.yml（坐标 + 旋转 + 备注）
Maven（vespera-world 模块把 layouts 与 schematics 摊到 target/world-assets）
      ↓  ./dev.sh 自动同步到 server/vespera/
粘贴（首次由管理命令批量贴上；正式服人工验收）
```

### 为什么 `region/` 永远不进 git

| 理由 | 说明 |
|---|---|
| 混了玩家数据 | 箱子、实体、玩家足迹都在 region 里。把玩家数据提交进仓库，等于把别人的东西发布出去 |
| 不可 diff | 二进制。改了哪一栋楼看不出来，code review 无从谈起 |
| 体量爆炸 | 8 区 × 500² 的 region 是 GB 级，clone 一次要半小时 |
| 合并即冲突 | 两个人同时改两个区，git 无法合并，只能"你的或我的" |

替代方案就是本仓库的做法：**建筑以 `.schem` 为单元，位置以 YAML 为清单。**
两个建筑同时改两栋楼，是两次互不冲突的文件改动。

### Maven 怎么管地图

```
vespera-world/src/main/resources/
├── regions/regions.yml      ← 坐标的唯一真相：区域范围、群系、标签、门规则
├── layouts/world.yml        ← 总平面：关系、手法、建设顺序、验收清单（不写坐标）
├── layouts/college.yml      ← 校区十一块建筑（坐标相对校区原点）
└── schematics/*.schem       ← 美术出的：二进制，LFS
        ↓ mvn process-resources（copy-resources）
vespera-world/target/world-assets/
        ↓ DevServer 同步
server/vespera/regions/ · layouts/ · schematics/
        ↓ 插件启动时读
RegionService（区域判定 + 下界门定向）
```

不做成 jar 是刻意的：地图资源必须在文件系统里**看得见、改得动**。藏进 jar 只会让美术
找不到自己的文件，让运维没法临时替换一栋楼。

### 建筑即机制：一张验收清单

设计书 1.3 那张表说"每一处建筑怪癖都能在判定表里找到原因"。这句话反过来就是验收标准——
建筑必须**真的**满足这些机制前提，否则设定就成了谎话：

| 建筑 | 机制前提 | 验收方式（建议做成 `/vespera check build`） |
|---|---|---|
| 回廊 | 从宿舍到教室全程不露天 | 沿线采样 `getLightFromSky() < 15` |
| 体育馆 | 有完整屋顶、无天窗 | 场馆内任意点天光 < 15 |
| 锅炉房 | 地下二层，常开下界传送门 | 传送门方块存在 + 恶魔归炉点可达 |
| 校医室 | 双门，后门通后山 | 两个出口，其一通向无建筑区域 |
| 宿舍 | 301 / 302 相邻，窗朝钟楼 | 房间坐标 + 朝向 |
| 旧校舍 | 夜间刷怪（不设保护） | 该区域无 WorldGuard 保护标志 |
| 祭坛 | 半径 7 格内黑曜石 ≥ 20 | **反向检查**：装饰性黑曜石不得超过阈值，否则玩家在装饰前右键金块会误转化 |

最后一条是最容易踩的坑，设计书 10.1 专门点过：**祭坛只需要"数量够"，不认"摆法"。**
所以吸血鬼祭坛附近不能有 20 块黑曜石装饰——这在建筑审图时就要拦住。

### 版权与来源

| 项 | 规矩 |
|---|---|
| 建筑 | 只放自己盖的。不复刻现实地标（教堂、钟楼、知名建筑） |
| `.schem` | 不用网上下载的建筑、别人的存档、付费地图包。"改了 30%"不是抗辩理由 |
| 地形 | WorldPainter 自绘；可以参照现实地貌类型，不照搬具体地点 |
| 音乐/音效 | 只用原版音效或自己做的。**音游曲目必须原创或有授权**——这是全项目最容易被追责的一处 |
| 贴图 | 若将来启用服务端资源包，全部自绘；不提取游戏内贴图，也不用网易中国版素材 |
