# 07 · 开发、调试、部署

三件事，三种节奏：**开发要能改、调试要能停、部署要能不动。** 混在一起做，三件都做不好。

---

## 一、三套环境，互不接触

| 环境 | 目录 | 端口 | 世界 | 谁用 | 怎么起 |
|---|---|---|---|---|---|
| **开发服** | `server/dev/` | 25565 | 保留，随便造 | 你 | `./dev.sh` 或 IDEA |
| **看建筑** | `server/showcase/` | 25599 | 平世界，每次可重建 | 你 | `Vespera 看建筑（平世界）` |
| **测试服** | `server/test/` | 25599 | 默认保留；`smoke` 时每次重建 | 自动化验证 | `./dev.sh test` / `smoke` |
| **正式服** | 你自己指定（如 `/srv/vespera`） | 由运维定 | 永不进仓库 | 运维 | `./deploy.sh` |

> 「看建筑」与「测试服」都用 25599，是因为它们不会同时开——一个给人看，一个给脚本跑。
> 撞上了也不要紧：启动器会探测端口，被占用就顺延，并把占用者名字打出来（例如
> `端口 25565 被占用（java pid 77719），改用 25566`），照着横幅进服即可。

## 一·五、想先进去看一眼建筑

**最快的一条路**（不需要改任何配置）：

1. IDEA 里选 **`Vespera 看建筑（平世界）`**，点 Run。
2. 控制台出现 `进服 localhost:25599`，用正版账号进。
3. 出生点就在校门外十二格，抬头是校门与钟楼。

为什么用平世界：地形是一块干净的白地，房子才看得清。真地形版本在开发服里——
但那边房子会跟你正在造的地形打架。

看过之后想改：平面数据在 `vespera-core` 的 `CampusPlan` 里，改完把
`VesperaPlugin.CAMPUS_VERSION` 加一，重开就会重建；也可以在控制台敲
`vespera build`（不用重启），再 `vespera verify` 看八处探针是否都通过。

图纸：`docs/设计图/学院平面图.html`（与游戏里的房子同源，都从 `CampusPlan` 生成）。

三条纪律，都是为了让三者永远不会互相踩：

| 纪律 | 做法 |
|---|---|
| **构建产物只有一处** | `server/build/plugins/vespera-plugin.jar`。每个环境**拷**一份，不做软链——软链会让"我这边升级"突然改变你正在测的那台服务器 |
| **一个目录同时只能有一个实例** | 启动时写 `.vespera.lock`（含 pid），进程还活着就拒跑。两个服务端共写一个世界，损失不是报错而是区块错乱，几小时后才发现 |
| **脚本不越界** | `dev.sh` 只碰 `server/dev` 与 `server/test`；`deploy.sh` 只写你给的目标目录，且只写 `plugins/` 与 `vespera/` |

共享的部分是刻意的：源码、构建产物、`server/build/paper.jar`（52 MB 的服务端本体，
下载一次三处用）。隔离的是**世界与插件状态**——那才是会打架的东西。

> 每个环境的 `libraries/` 与 `versions/` 仍是各自一份，Paper 自己解压。
> 那部分和版本强相关，共用一个反而容易出事，宁可多占点盘。

## 二、在 IDEA 里调试

### 先说清楚为什么不能直接打断点

```
IDEA Debug  ──→  DevServer（启动器，一个 JVM）
                     └─ 启动 ──→ paper.jar（服务端，另一个 JVM）
                                      └─ 你的插件活在这里
```

在启动器上打断点，**永远打不中插件**。这是第一次用这套东西最常见的困惑，也是
`DevServer` 为什么要在服务端那个 JVM 上单独开一个 JDWP 端口的原因。

### 姿势 A：Run 起服，再 attach（日常用这个）

1. 运行配置里选 **`Vespera 开发服`**（仓库自带的，见 `.run/`），点 **Run**。
2. 控制台会打出：
   ```
   插件调试  IDEA → Run → Attach to Process → 选 paper.jar（端口 5005）
            或 Debug 一个 Remote JVM Debug：127.0.0.1:5005
   ```
3. 运行配置里选 **`插件调试 (attach 5005)`**，点 **Debug**。
4. 现在插件里的断点会停。改代码 → 重新 Run → 重新 attach（服务端进程换了，旧连接会断）。

也可以用 IDEA 的 **Run → Attach to Process**，在列表里挑 `paper.jar`——效果一样，不用配置。

### 姿势 B：等调试器（要断 `onEnable` 用这个）

1. 选 **`Vespera 开发服（等调试器）`**，Run。
2. 服务端会在第一行代码前停住（`suspend=y`），控制台提示等待。
3. Debug **`插件调试 (attach 5005)`**。
4. 这才能在 `onEnable` 里打断点——姿势 A 里 `onEnable` 早就跑完了。

### 姿势 C：命令行

```bash
./dev.sh debug        # 开发服 + 5005 端口，然后 attach
```

### 三个会让人以为"断点坏了"的坑

| 现象 | 真实原因 | 怎么办 |
|---|---|---|
| 断点图标变成灰色/空心 | 跑的是旧 jar（源码改了没打包） | `DevServer` 会自动 `mvn package`；看到"先打一次包"就是它在补。也可 `-Dvespera.build=false` 关掉后手动打 |
| 能连上但从来不进断点 | `suspend=n`，`onEnable` 已经跑过 | 用姿势 B，或把断点打在事件回调里 |
| attach 提示端口已占用 | 上一个服务端没退干净 | `./dev.sh` 的输出里会写实际端口（5005 被占会往后找）；先 `stop` 或杀掉旧进程 |

## 三、部署

```bash
./deploy.sh                 # 产出 dist/
./deploy.sh /srv/vespera    # 直接放进目标目录
```

包里只有三样：

```
dist/
├── plugins/vespera-plugin.jar   → 服务器/plugins/
├── vespera/                     → 服务器/vespera/（区域表、布置清单、结构文件）
└── 放置说明.txt                  → 该覆盖什么、不该覆盖什么
```

**故意不放进包里的：** `server.properties`（白名单、正版验证、端口属于那台机器）、
`world/`（世界与玩家数据）、其它第三方插件 jar（各自独立升级）。

部署之后第一件事不是进游戏，是敲一条：

```
vespera doctor
```

版本、软依赖、区域、闸门、剧本——一次看全。**上线事故里最常见的一种，是"部署了但没生效"**，
而这条命令专门用来排除它。

## 四、常见故障

| 症状 | 原因 | 处置 |
|---|---|---|
| 启动报"目录已被占用" | 同目录还有实例在跑 | 停掉旧的；开发服与测试服本来就该用不同目录 |
| `Address already in use: bind` | 端口被别的程序占着（另一个仓库的测试服、上次没退干净的进程） | **现在会自动顺延**并打印占用者，直接用横幅里那个端口进服。想守住原端口：`lsof -nP -iTCP:25565 -sTCP:LISTEN` 找到进程停掉，或用 `-Dvespera.port=25xxx` 指定 |
| IDEA 提示 module `vespera-dev` 不存在 | Maven 工程没导入，或模块名不同 | 右键 `pom.xml` → Add as Maven Project；或把配置里的 module 改成实际的模块名 |
| 进服被拒（认证失败） | `online-mode=true`，需要正版账号 | 用正版登录；**不要**为了图方便关掉它 |
| 世界被清空了 | 对 `server/test` 跑了 `smoke`（它就是每次重建） | 开发服在 `server/dev`，冒烟只碰测试服 |
| 聊天栏的 `[选项]` 点不动 | 客户端版本 < 可点击组件支持，或回调过期 | 换 Paper 26.3 对应的客户端版本；重开一次对话 |

## 五、给自动化验证留的位置

我的验证只走测试服，永远不碰 `server/dev`：

```bash
./dev.sh smoke    # 起 → 敲 /vespera doctor → 每个对话节点构造一遍 → 退，退出码即结论
```

它能挡住的问题，恰好是人工最容易漏的那一类：剧本读不出来、闸门配置错、区域表坐标写错、
插件根本没加载。**它挡不住的是手感**——那必须你亲自进服走一遍。
