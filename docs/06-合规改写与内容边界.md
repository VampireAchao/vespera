# 06 · 合规改写与内容边界

## 立场

服务器是私人 / 受邀的，大概率只有作者一个人会进。但**"私人"不等于"可以直说"**。

原因很朴素：真正会出事的时刻不是玩家在线的时候，是**某张截图被发出去**的时候。
所以这里的规则不是写给玩家看的，是写给"万一被看见"那一刻准备的。

三道防线，从外到内：

| 层 | 做什么 | 在哪 |
|---|---|---|
| 服务器 | 白名单、不公开、不推广、无遥测 | `server.properties` + 运维纪律 |
| 内容 | 闸门默认关，关着的线不生成 | `content.yml` + `ContentPolicy` |
| 文本 | 不命名、不解释、不描写 | 剧本写法（本篇第三节） |

---

## 一、三类题材的改写表

原则先立：**保留叙事功能，删掉表面指认。**

一段剧情之所以重要，是因为它让玩家感到"身份不由自己决定""有人替我说话""规矩是冷的"。
这三个感受不需要任何敏感词就能成立——需要的只是**把它们换成机制与物件**。

### 1. 原来写"性别转换"的那条线 → 改写为「名籍」

| 项 | 内容 |
|---|---|
| 明面上是什么 | 一份登记表、别人怎么叫你、一张学生证上的一行字 |
| 玩家看到什么 | 有人在名册上划掉一个字重写；有人叫错了你的名字；有人坚持用旧的那个 |
| 机制落点 | 计数 `enrolled_name`（学籍名）+ 称谓变量 `${you}`；旧镜（黑曜石框 + 水源）只在 `isSuper()` 时可用，作用不解释 |
| 保留的功能 | 身份被制度定义、被他人目光检验；"改回来或一直改"的两难 |
| 删掉的 | 身体、镜子前的场景、任何以"变成什么"为卖点的表述、取向与性别标签 |

对白示例（`bonds` 闸门关闭时它根本不存在，见第四节）：

```yaml
      - label: "（把名册上那个字描了一遍。）"
        tell: "墨迹在纸上洇开一点。你把它合上了。"
```

一句"描了一遍"，比十句解释更疼。而且它不指认任何东西——不知道背景的人读起来，
就是一个学生在看自己的名字。

### 2. 原来写"同性恋爱"的那条线 → 改写为「羁绊」

| 项 | 内容 |
|---|---|
| 明面上是什么 | 谁愿意为你多跑一趟；谁在你回来时还醒着 |
| 玩家看到什么 | 一句没说完的话、一件借了没还的外套、一个没说出口的停顿 |
| 机制落点 | 好感 `aff_<id>` + 羁绊三级；"告白窗口"改称"把话说完"，不给关系贴标签 |
| 保留的功能 | 亲密关系的重量、选择的不可逆 |
| 删掉的 | 恋人称谓、性别指向、任何身体接触的描写、任何"出柜"式的宣示 |

改写要点：**把"关系"写成"行为"，不写成"身份"。**
不写"她喜欢你"，写"她把外套借给你，说明天还，但第二天没提"。

### 3. 原来写"校园霸凌"的那条线 → 改写为「规矩」

| 项 | 内容 |
|---|---|
| 明面上是什么 | 桌上的一张纸、没人接的一句话、被挪开的椅子 |
| 玩家看到什么 | 结果，不是过程；反弹，不是加害 |
| 机制落点 | 旗标 `saw_paper` / `spoke_up`；反制选项必须有回报（有人开始跟你说话） |
| 保留的功能 | 制度性冷漠、旁观者的选择 |
| 删掉的 | 施暴过程、加害者的动机独白、受害的细节描写、"霸凌"这个词本身 |

改写要点：**镜头永远在门外。** 玩家看见的是"第二天她把椅子挪远了一点"，
而不是"她被推倒"。这样写，既不轻，也不脏。

### 4. 私密场景 → 改写为「门」

| 项 | 内容 |
|---|---|
| 明面上是什么 | 一扇关着的门、门外的脚步声、第二天早上的一句"你睡了吗" |
| 机制落点 | 区域判定 + `privacy` 闸门；一切交互在区域外完成 |
| 保留的功能 | 留白本身 |
| 删掉的 | 室内的一切 |

## 二、四类词的禁词表

写台词时逐条对照。**P1 会做成启动时扫描**（`docs/04` 缺失项 5），先人工守。

| 类别 | 禁词（示例，非穷举） | 替代写法 |
|---|---|---|
| **题材命名** | 霸凌、欺负、孤立、排挤、同性恋、取向、变性、性别转换、出柜 | 不写。写具体发生过的那一件事 |
| **身体与亲密** | 任何身体部位、拥抱、亲吻、触碰的描写 | 停在门口。写门外、写第二天 |
| **机制与数值** | 血势、伤害、冷却、概率、背包、任务、按 F、左键、读档、重生点 | "青筋暗了一格""你的手臂还在抖" |
| **元信息** | 玩家 ID、名字颜色、称号标签、等级、经验条 | NPC 用称号："学徒""提灯的人" |

一条自检：**把这段台词给一个没读过设定的人看。**
如果他读出了一个"题材"，说明写得太明；如果他只读出"一个人不太舒服"，说明写对了。

## 三、代码里的三道闸

| 闸 | 位置 | 默认 | 行为 |
|---|---|---|---|
| 图级 `gate` | 剧本 YAML 顶部 | 关 | 整张图不生成；右键 NPC 只得到「今天没什么可说的。」 |
| 选项级 `gate` | 单个选项 | 关 | 该选项不进界面；**不留灰按钮**——灰按钮等于说"这里有东西" |
| 未登记的闸门名 | `content.yml` 没有这个键 | 关 | 拼错、改名、手滑注释掉 → 一律不通 |

失败方向必须朝安全那边，这是唯一一条不能商量的工程原则。

```yaml
# content.yml —— 三道闸，全关
gates:
  bonds: false      # 关系线往深处走的那几场
  privacy: false    # 门后面的一切
  conflict: false   # 纸、椅子、没人接的话
```

关着的时候，`/vespera doctor` 会显示 `内容闸门  3 道，全部关闭`。
这是唯一能看到它们存在的地方——玩家那边没有痕迹。

## 四、私人服务器的九条纪律

代码管得住内容，管不住"被看见"。九条，都很好执行：

| # | 纪律 | 为什么 |
|---|---|---|
| 1 | `white-list=true` + `enforce-whitelist=true` | 唯一的入口控制。比任何反作弊都有效 |
| 2 | `online-mode=true` | 不开离线验证，就没有冒名顶替这回事 |
| 3 | 不在服务器列表公开（关掉查询广播） | 不出现，就不会被扫描到 |
| 4 | 关掉 bStats | 无条件外发的统计，没有理由留着 |
| 5 | 不录屏、不直播、不把截图发到公开群 | **这是唯一真实的泄漏路径**。九条里最重要的一条 |
| 6 | 日志只在本机，保留 30 天 | 日志里全是聊天与命令 |
| 7 | 不接第三方皮肤签名服务 | 一接，玩家的皮肤 URL 就出境了 |
| 8 | 存档备份放私有位置，不进任何云盘共享链接 | 存档里是全部剧情状态 |
| 9 | 万一外传：先停服、关闸、再谈 | 顺序不能反。先解释只会扩大传播 |

第 5 条值得再说一句：这个项目最大的合规风险不在服务器里，在**分享欲**里。
一段写得好的戏，第一反应是截图发给朋友——那一秒，所有闸门都失效了。

## 五、如果哪天想公开

现在这套设计是"能公开的形状"，但公开是另一件事，成本清单摆在这里：

| 项 | 现状 | 公开需要 |
|---|---|---|
| 版号 | 无 | 公开运营的前置条件，没有就不能公开 |
| 实名与防沉迷 | 无 | 按现行规定接入 |
| 内容审查 | 靠闸门自觉 | 需要逐条过一遍文本，且题材本身可能需要删改 |
| 未成年人保护 | 私人不需要 | 准入、家长通道、举报机制 |
| 数据与隐私 | 本机 | 隐私政策、删除权、跨境说明 |

结论：**公开不是"多开几个人"，是换一个产品。** 在那之前，私人形态是最优解。

## 六、改写之后，文本反而更好

这不是安慰。三件事真的变好了：

**其一，留白比描写有力。** 不写"她在哭"，写"她把纸折起来，动作很轻，像在收一件易碎的东西"。
镜头退后一步，读者的想象往前走一步。

**其二，机制比台词硬。** 身份不再是一段过场动画，而是登记表上的一个字、别人嘴里的一声称呼。
玩家不需要被告知"这很重要"，他会自己发现改不回来。

**其三，删掉解释，推理就成了内容。** 玩家会问"那张纸是谁写的"——这个问题比我写十句答案都值钱。

> 合规改写最怕的是"删到没东西"。这里不是删，是换：把**说出来的**换成**发生过的**。
> 说出来的会过期，发生过的不会。
